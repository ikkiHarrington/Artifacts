# 02-button: ボタンと割り込み

タクトスイッチ 2 つの入力を、**ポーリング**(自分で何度も見に行く)と**割り込み**(変化したらハードウェアが知らせてくる)の 2 通りで読む。

組み込み特有の部分(GPIO 入力の設定、ピンの読み取り、割り込みの登録、`volatile`、チャタリング対策)は、[main.c](main.c) の `TODO` として空けてある。**自分で調べて実装する**。表示やループなど、それ以外の部分は書いてある。

ヒントは課題ごとに 2 段階ある。まず「調べる場所」だけを見て、詰まったら折りたたみの「答えに近いヒント」を開く。

## 準備

1. 01 の配線(Debug Probe の D ポートと U ポート)はそのまま使う。
2. タクトスイッチを、SW1 は GP14 と GND、SW2 は GP15 と GND の間につなぐ(配線図は [../README.md](../README.md#タクトスイッチ02-以降で使う))。
3. VS Code で **このフォルダ(`pico/02-button`)を開く**。
4. `TODO` のままでもビルドと書き込みはできる。最初に一度ビルドし、`02-button: mode=polling` がシリアルに出ることを確かめておく。

## 課題 1:ポーリングで SW1 を読む

`MODE` は `MODE_POLLING` のまま。`sw1_init()` と `sw1_pressed()` を実装する。

**できたら**:SW1 を押すと `SW1 pressed`、離すと `SW1 released` と出て、押している間だけ LED が点く。

**確かめること**
1. デバッガで止めて、XPERIPHERALS の `SIO` → `GPIO_IN` を開く。SW1 を押したままと離したままで、bit 14 がどう変わるかを見る。
2. プルアップを有効にする行を消して試す。押していないときの値がどうなるか(安定するか)を見て、プルアップが何のためにあるかを説明できるようにする。
3. `POLL_INTERVAL_MS` を `0` にして、SW1 をゆっくり何回か押す。1 回押しただけで `pressed` と `released` が何回も出ることがある。これが**チャタリング**。`10` に戻すとほぼ出なくなる理由を考える(課題 4 につながる)。

<details>
<summary>答えに近いヒント</summary>

- 使う関数は `gpio_init`、`gpio_set_dir`、`gpio_pull_up`、`gpio_get` の 4 つ。
- プルアップでは、押していないときが High(1)、押したときが Low(0)。「押されている」は値が 0 のとき。
- プルアップの設定は、XPERIPHERALS の `PADS_BANK0` → `GPIO14` の `PUE` ビットでも見える。

</details>

## 課題 2:割り込みで SW2 を数える

`MODE` を `MODE_INTERRUPT` に変える。割り込みで呼ばれる関数を書き、`sw2_init()` で登録する。

**できたら**:SW2 を押すたびに `SW2 count=1`、`2`、… と出て、LED が交互に点く。

**確かめること**
1. 割り込みで呼ばれる関数の先頭にブレークポイントを置き、SW2 を押して止まるかを見る。CALL STACK を見ると、`main` から呼んでいないのに呼ばれていることが分かる。
2. 「押したとき」だけ数えるには、どの変化(High→Low か、Low→High か)で割り込みを起こせばよいかを考える。
3. 課題 1 のポーリングとの違いを、自分の言葉で説明できるようにする。CPU が何をしている時間が長いか、押した瞬間をどちらが取りこぼしにくいか、という観点で考える。

**注意**:割り込みの関数の中では `printf` を使わない。割り込みの関数は、短く終わらせるのが原則。表示は `run_interrupt()` に任せてある。

<details>
<summary>答えに近いヒント</summary>

- 登録には `gpio_set_irq_enabled_with_callback` を使う。
- 呼ばれる関数の形は `void 関数名(uint gpio, uint32_t event_mask)`(`gpio.h` の `gpio_irq_callback_t`)。`gpio` には、割り込みを起こしたピンの番号が入る。
- 押したとき(High→Low)は「立ち下がり」。`GPIO_IRQ_EDGE_FALL` で指定する。
- 公式のサンプル [pico-examples の hello_gpio_irq](https://github.com/raspberrypi/pico-examples/tree/master/gpio/hello_gpio_irq) が、ほぼそのままの形で参考になる。

</details>

## 課題 3:`volatile` がないと何が起きるか

`sw2_count` の宣言は、わざと足りないままにしてある。課題 2 が正しくできていても、**SW2 を押しても何も表示されない**はず。

**確かめること**
1. SW2 を何回か押したあと、デバッガで一時停止(`F6`)する。止まった場所と、そのときの `sw2_count` の値を見る(WATCH に `sw2_count` を足すとよい)。
2. 割り込みの関数は呼ばれ、`sw2_count` も増えているのに、なぜ待ちループを抜けないのかを調べる。止まった場所で右クリック →「Open Disassembly View」で、待ちループがどんな命令になっているかを見るのが近道。
3. 宣言を直して、表示されるようになることを確かめる。直したあと、同じ逆アセンブル(Disassembly)が変わったかも見る。

<details>
<summary>答えに近いヒント</summary>

- コンパイラは、`while (sw2_count == last)` のループの中で `sw2_count` を書き換える処理がないので、「この値は変わらない」と判断する。そのため値を 1 回だけ読み、あとは読み直さない無限ループにしてしまう。Debug ビルド(`-Og`)でもこうなる。
- 割り込みの関数のように、プログラムの流れの外から書き換わる変数には `volatile` を付ける。付けると、コンパイラは使うたびにメモリから読み直す。

</details>

## 課題 4:チャタリングを取る

スイッチの中の金属が接触するとき、細かく何回か跳ねて、つながったり離れたりする。割り込みはこの 1 回 1 回に反応するので、1 回押しただけで 2 以上数えることがある。

**確かめること**
1. まず対策なしで SW2 を何十回か押し、`count` が 1 回の押下で 2 以上進むことがあるかを見る。離したときに数えてしまうこともある。
2. 割り込みの関数の中で、1 回押しただけでは 1 しか増えないようにする。
3. 対策した後に、素早く連打しても取りこぼさないかを見る。チャタリング対策が強すぎると、本当の連打まで捨ててしまう。

<details>
<summary>答えに近いヒント</summary>

- よくある方法は「前回数えてから一定時間(数十 ms)以内の割り込みは無視する」。
- 起動からの時間は、`time_us_32()`(`hardware/timer.h`)や `to_ms_since_boot(get_absolute_time())`(`pico/time.h`)で取れる。どちらも `pico/stdlib.h` から読み込まれている。
- 前回の時刻は、割り込みの関数が呼ばれ終わっても残るように覚えておく(`static` 変数など)。
- 課題 1 の 3 で `POLL_INTERVAL_MS` を `10` にするとチャタリングが出にくくなったのも、跳ねている間を飛ばして読んでいるため。

</details>
