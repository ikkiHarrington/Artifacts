# 機密データを扱うローカル AI アプリの作り方

`portfolio/`(資産レビュー)を作る中で決めたこと・失敗したことをまとめた手順。新しいアプリでも、既存アプリの改修でも、上から順に確認する。

## 1. 最初にデータの境界をユーザーと決める

コードを書く前に、次の3つを確認し、CLAUDE.md に書く。

| 境界 | portfolio で決めたこと |
|---|---|
| 開発者(Claude)が見てよいもの | 実データは**マスク済みでも**読まない・開かない・集計しない。ユーザーの条件は「あなたが私の資産の内容を見ないならOK」 |
| アプリが AI に送ってよいもの | 割合・損益率・指数・銘柄名(銘柄名はオンオフ可)。金額・数量・単価・総資産額・id は送らない |
| 保存場所 | `data/` を `.gitignore` に入れる。`.env*` と `logs/` も入れる |

- 動作確認は、データのパスを環境変数(例:`PORTFOLIO_DATA_PATH`)でスクラッチパッドに向け、架空のデータ(`*.fixture.ts`)だけで行う。
- 実データでしか確かめられないこと(取り込んだ CSV の形など)は、ユーザーに実行してもらい、結果を言葉で聞く。
- ユーザーが実データでサーバーを動かしている間(そのポートが応答している間)は、そのポートをブラウザで開かない。そのフォルダで `next build` もしない(`.next` を上書きして、動いているサーバーを壊すため)。

## 2. マスクは「送ってよい項目だけを残す」形で作る

- 送信用の文字列を作る関数を1か所(`src/lib/mask.ts`)にまとめる。項目を消していく(拒否リスト)のではなく、送る項目を選ぶ(許可リスト)形にする。
- テストに**「含まない」テスト**を入れる。架空データの金額・数量・単価・id の文字列が出力に現れないことを確かめる。送る内容を変えるときは、このテストも必ず更新する。
- 画面に「送信内容を確認」を置き、実際に送る文字列とプロンプトを、ユーザーが送信前に見られるようにする。

## 3. AI の呼び出し

- `AiProvider` インターフェースを作り、環境変数で切り替える。`claude`(API キー)、`claude-code`(サブスクで `claude -p`)、`ollama` などのスタブを用意する。
- `claude -p` を子プロセスで呼ぶときの決まりごと(`src/lib/ai/claudeCode.ts`):
  - `--tools ""` と `--strict-mcp-config` を付けて、ツールと MCP を無効にする。プロンプトにどんな指示が入っても、AI がファイルを読めないようにするため。
  - `--no-session-persistence` を付け、作業フォルダは空の一時フォルダにする。リポジトリの CLAUDE.md や実データを読み込ませないため。
  - 子プロセスの環境変数から `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` を外す。残すとサブスクではなく API の従量課金になる。
  - 標準出力は `setEncoding("utf8")` で受ける。日本語の文字がチャンクの境目で分かれて化けるのを防ぐため。
- AI の呼び出しは、**ボタンを押したときだけ**にする。画面表示・定期実行・価格更新に連動した自動呼び出しは作らない(費用と、意図しないデータ送信を避けるため)。

## 4. プロンプトはビルドなしで変えられるようにする

- プロンプトは `prompts/*.md` に置き、AI を呼ぶたびに読む。ファイルがない・空・読めないときは、コードに書いた既定のプロンプトに戻す(`src/lib/ai/prompts.ts`)。
- `<!-- -->` のコメントはメモとして取り除いてから送る。ファイル先頭の説明コメントの中に `<!-- -->` を書かない(そこでコメントが閉じてしまう)。
- `fs` の呼び出しには `/*turbopackIgnore: true*/` を付ける。付けないと、Turbopack がビルド時にファイルを取り込もうとする。
- テストでは、ファイルの**中身を固定しない**(ユーザーが自由に編集するため)。確かめるのは「書き換えが次の呼び出しに反映される」「なければ既定に戻る」「コメントが残らない」こと。
- プレビューには、プロンプトの本文と読み込み元(ファイルか既定か)も表示する。

## 5. プロンプトを改善するループ

1. 確かめたい論点を仕込んだ**架空のデータセット**を2種類以上作る。例:指数ファンドの重複、業種の偏り、価格の未取得、途中の入金、含み損、現金が過半、推移の記録が1件だけ。
2. オプトインの評価テストを作る(例:`reviewPrompt.eval.test.ts`)。環境変数(`PROMPT_OUT`)を指定したときだけ動き、普段の `npm test` では skip される。入力と出力をファイルに書き出す。
3. 出力を読み、問題を1つずつプロンプトの規則に直して、もう一度実行する。これを5回ほど繰り返す。
4. portfolio で実際に出た失敗(新しいアプリでも最初に確かめる):
   - 比率と損益率から、伏せた金額を逆算する。
   - 「未取得」を「売却済み」と誤読する。記録日と基準日のずれを「集計の誤り」と書く。
   - 購入時期の違う累計損益率どうしを比べて、最近の値動きの向きを推論する。
   - 売買を勧める(「利益確定」「損切り」を含む)。判断基準を点検する問いの形にさせる。
   - アプリの使い方について助言する。
   - 長すぎる、表を使う、見出しをまたいで同じ事実を繰り返す、単位の書き方がばらつく。
5. 対策として効いたのは次の3つ。字数の上限と見出しの構成を明示する。各見出しに「何行・何項目」を指定する。データの意味(何を含むか、何を意味しないか)をシステムプロンプトに書く。

## 6. AI の回答の表示

- 回答は Markdown として描画する。HTML として埋め込まず、パースした結果を React 要素にして描く(`innerHTML` を使わない。XSS を防ぐため)。`**` などの記号を生のまま見せない。
- 長いレポートには「大きく表示」(ダイアログ、Esc で閉じる)を付ける。

## 7. Windows でのローカル常駐

- 起動用 `.bat` は、`next start` を PowerShell の `Start-Process -WindowStyle Hidden` で裏で起動して、すぐ終わる形にする。cmd の窓を閉じると止まる作りにすると、ユーザーには「Failed to fetch」としか見えない。
- 起動 bat の中身:
  - すでにサーバーが応答していれば、ブラウザを開くだけにする。
  - `node_modules` がなければ `npm install` する。
  - `.next/BUILD_ID` よりソースが新しければ `npm run build` する。
  - ログは `logs/` に出す。
- 停止用 `.bat` は、そのポートで待ち受けている `node` のプロセスだけを止める(`Get-NetTCPConnection`)。
- `.bat` は CRLF + UTF-8 で保存し、先頭で `chcp 65001` を実行する。
- Next.js 16 は、同じフォルダで開発サーバーを2つ起動できない。ユーザーのサーバーが動いている間の確認は、テストで行う。

## 8. セキュリティの確認項目

- サーバーは `127.0.0.1` だけで待ち受ける。
- `proxy.ts`(Next.js 16 の middleware)で次の2つを確認する。127.0.0.1 で待ち受けていても、ブラウザで開いた悪意のあるサイトからは届いてしまうため。
  - `Host` ヘッダーが `127.0.0.1:<port>` / `localhost:<port>` であること。DNS リバインディングでデータを読まれるのを防ぐ。
  - GET 以外のリクエストは、`Origin` がアプリ自身であること。CSRF で AI の呼び出しや書き込みを勝手に実行されるのを防ぐ。
- `prompts/*.md` は Git の管理下にあるので、個人の数値を書かないようユーザーに伝える。
- コミットするファイルは個別に指定する。`data/`、`.env*`、`logs/` が含まれていないことを毎回確かめる。

## 9. UI の決めごと

- 損益の色はユーザーに確認する(portfolio では、利益(+)が緑、損失(−)が赤)。色はテーマのトークン(`--color-gain` / `--color-loss`)と判定関数(`pnlTextClass`)にまとめる。色だけに頼らず、必ず符号も付ける。
- 画面の大きな変更は、案を複数作ってユーザーに選んでもらってから実装する(portfolio では Claude Design で A〜C 案を作り、C 案を選んでもらった)。

## 10. このリポジトリでつまずいたこと

- Git Bash から `npx vitest` を実行すると「failed to find the current suite」で失敗する。テストは PowerShell から実行する。
- コードを Python の文字列(heredoc)経由で書くと、`\\n` が本物の改行に変わって壊れる。コードの編集には Edit ツールを使う。
- ユーザーのフィードバック(色、表示、プロンプトの扱いなど)は、その場で直すだけでなく、CLAUDE.md のプロジェクト項目にルールとして書き足す。
