お出かけプランは、以下の順で進めてください。

## 1. 条件を整理する

ユーザーの発言から次を拾う。足りないものは、デフォルトを置いて進めるか、答えで行程が大きく変わる場合だけ聞く。

- 日付と曜日(混雑・渋滞の見込みに効く)
- 出発地・出発時刻
- 目的地、食事の店、見たいもの(紅葉・花など)
- 移動手段(車か電車か)
- 順序の希望(例:先に食事)

## 2. 調べて裏取りする

WebSearch で次を確認する。検索は独立したものを並行して投げる。

- 店の営業時間・定休日・電話番号
- イベントや見頃の開催期間(開催年を確認する。去年の情報を今年のものとして使わない)
- 駐車場の有無・台数・料金(無料か有料か)
- 周辺のおすすめスポット・カフェ
- 車の場合は渋滞しやすい区間と時間帯

裏取りのルール:
- 検索結果に出てきた事実だけを書く。出ていない料金・所要時間・URLは推測で書かない。
- 情報源どうしが食い違うときは、表にして並べるか、両方を併記する。どれかに決め打ちしない。
- 去年の情報や古い記事は、そう分かるように注記する。
- 営業時間や料金は変わるので、「訪問前に確認」と電話番号などの問い合わせ先を添える。

## 3. 行程を組む

- 時刻は表にする(時刻 / 内容 / メモ)。
- 到着時刻は、混雑する曜日なら余裕を見て少し遅めに置く。
- 食事の店は混雑を避けるため、ピーク前に入る時刻にする。
- 順序の希望(先に食事など)を最優先で守り、時間配分をそれに合わせる。
- 車での帰りは、渋滞する時間帯を避ける出発時刻を提案する。避けられない場合は代替案(夜遅くに出るなど)を添える。

## 4. 補足を付ける

求められたら、または有用なら次を追加する。

- 駐車場(無料・有料)の一覧表。情報源ごとの食い違いも載せる
- 高速代を抑える別ルート。料金と所要時間が確認できていない場合は、その旨を明記する。安全面(凍結など)の注意も添える
- おすすめスポットとカフェ(リンク付き)
- 持ち物

## 5. Markdownにまとめる

- 1つのMarkdownファイルにまとめる(例:`<行き先>-plan.md`)。
- 見出し:タイムライン / イベント情報 / 駐車場 / 高速代を抑えるプラン / おすすめスポット / おすすめカフェ / 渋滞対策 / 持ち物
- リンクは、検索で実際に出てきたページだけを貼る。個別店舗の公式URLが分からなければ、特集記事へのリンクにとどめる。
- 画像など別形式を頼まれたときも、内容はこの行程を元に作る。形式を変えたら、不要になった中間ファイルは削除してよいか確認するか、頼まれたら削除する。

## 6. 報告する

最後に次を短く伝える。

- 書いたファイルの場所
- 裏取りできなかった点、情報源の食い違い、古い情報だった点
- 次に決めたいこと(ライトアップを見るか、寄り道を増やすかなど)

## コミットするとき

ユーザーに頼まれたときだけコミット・pushする。mainブランチ上なら、まず作業用ブランチを切る。自分が作ったファイルだけを add し、既存の未追跡ファイルは含めない。
