# portfolio コードベース勉強会(全6回):型・計算・保存・画面・CSV・AI

資産管理アプリ portfolio のコードを、全6回に分けて順に読みました。普段 Web アプリを開発しないとのことだったので、途中からは文法や React のポイントも合わせて説明し、第6回まで終えました。

## 決まったこと・ルール
- 勉強では、コードを読みながら、出てくる文法もその都度説明する(React.js などのポイントも含める)
- 第2回で気づいた重複した計算の書き換えは見送り、勉強を先に進めた

## 説明したこと(学んだこと)

全体の流れは「画面(`components/`)⇄ 窓口(`app/api/`)⇄ 保存ファイル(`data/*.json`)」です。AI に相談するときは、`mask.ts` が金額などを消してから送ります。全体に共通するのは「外から来るものは入口で検品し、外へ出すものは出口で黒塗りする」という設計です。

### 第1回:データの形(`src/types/portfolio.ts`)
- 使われている言語は TypeScript(JavaScript に「型」を足したもの)。`interface` はデータの書式の定義で、`?` が付いた項目は省略できる
- 型のチェックが効くのは書いている間だけ。外から来るデータは、実行時に別途確認する(`isAssetClass` など)
- `as const` で種類の一覧から型を作れる。`Record` は対応表
- 投資信託の価格は「1万口あたり」なので、評価額の計算で 10000 で割る

### 第2回:計算(`src/lib/data/portfolio.ts`)
- 役割は集計、入力の検品、推移の記録の3つ
- 一覧を扱う道具:`map`(全件を加工)、`filter`(条件で抜き出す)、`reduce`(1つにまとめる)、`sort`(並べ替え)、`flatMap`(加工しつつ不要なものを消す)
- 記号:アロー関数(短い関数)、`条件 ? A : B`(1行の if)、`===`(等しい)、`...`(中身を広げる)
- 読み込んだデータに壊れた件があれば、その件だけを捨てる
- 同じ入力に同じ答えを返し、ほかに何も触らない関数を「純粋関数」という。テストしやすい

**質問:`marketValue(h)` の計算は冗長か?**
- `summarize` の中で1件の評価額を3回計算していて、`costBasis` も2回計算している。`takeSnapshot` は `summarize` の結果の一部しか使っていない
- 速さは問題なく、気になるのは読みやすさの面。比率を出すには先に合計が必要なので、2周の処理は必要
- 直すなら、最初に1回だけ計算した結果を使い回す。どちらの書き方も間違いではない

### 第3回:保存と窓口
- コードは、ブラウザ(画面)とサーバー(ファイルを扱う裏方)の2か所で動く。やりとりは HTTP(Web の注文の決まり)と JSON(データを文字にしたもの)
- `await` は返事を待つ書き方。`Promise` は「あとで結果が届く引換券」
- フォルダの場所が窓口の住所になる(`app/api/portfolio/route.ts` → `/api/portfolio`)
- 返事の番号:200 は成功、400 は注文側の不備、500 はサーバー側の失敗
- 画面でチェックしていても、窓口でもう一度検品する
- 保存ファイルが壊れていたらエラーにする(空データで上書きしないため)。保存は下書きファイルに書いてから差し替える

**質問:`requestJson` でジェネリクス(`<T>`、中身の型をあとで決める書き方)を使う理由は?**
- 返事の形が違う窓口を、共通の1つの関数で扱いながら、型のチェックも効かせるため。宛名欄が空いた封筒のようなもの
- ただし `as T` は「そう信じる」という宣言で、中身は確認していない。このアプリは自分の窓口が相手なので信じているが、外部サービスの返事は受け取り側でも検品するのが安全

### 第4回:画面(React)
- React は、データを変えると画面を描き直してくれる。Excel の再計算に似ている
- 部品(コンポーネント)は、親から受け取る値(props)をもとに画面を返す関数。HTML のような書き方は JSX
- データは親の `Dashboard` だけが持つ。データは下へ渡し、ボタン操作などは上へ知らせる
- `useState`:覚えておくデータ。変えるときは必ず `set〜` を使う
- `useEffect`:画面が出たあとの処理(ここでは最初のデータ取得)
- `useMemo`:計算結果のメモ。第2回で気にした「何度も計算する問題」への React 流の対策で、`data` が変わったときだけ計算し直す
- `useRef`:画面の要素を指さす(入力欄までのスクロールに使用)
- 一覧表示の `key` は、各行を見分ける名札
- `"use client"` はブラウザで動かす宣言。`className` の短い単語(Tailwind)は見た目の指定

### 第5回:CSV 取り込み(`src/lib/import/`)
- 流れは、ファイル選択 → 文字に変換(楽天証券は Shift_JIS という古い日本語の文字コード)→ 表に分割 → 保有データに変換 → 台帳と入れ替え
- 金額の中にもカンマがあるので、単純にカンマでは割れない。引用符の中かどうかを覚えながら1文字ずつ読む
- 列は番号ではなく見出し名で探す。数値の整形には正規表現(文字のパターン指定)を使う
- 同じ銘柄の複数行はまとめ、取得単価は株数で重みを付けて平均する
- CSV の評価額と照合し、ずれが大きければ警告する。表全体の不備は中止、1行だけの不備はその行を飛ばす
- 再取り込みで入れ替わるのは楽天由来の分だけで、手入力の分は残る
- 楽天の CSV では、円の預り金だけ明細ではなく上の「資産合計欄」から取る

### 第6回:AI とマスク
- AI に送るのは割合、損益率、集中度、推移の指数(最初を 100 とした値)など。金額、数量、単価、`id` は送らない
- 銘柄名は送るかどうかを切り替えられる(初期設定は送る)。オフにすると「銘柄A」などになる
- 画面のプレビューと実際の送信は、同じ処理で作った内容を使う。黒塗りはテストでも見張り、AI への指示文でも金額の推測を禁じている
- 指示文(`prompts/*.md`)は毎回読み込むので、書き換えれば次のレポートから反映される。読めないときは既定の指示文を使う
- AI の接続先は共通の形(`AiProvider`)で差し替えられる。`claude`(API キー、従量課金)、`claude-code`(サブスクのログイン)、`ollama`(手元の AI 用の仮の差し込み口)があり、環境変数(外から渡す設定値)の `AI_PROVIDER` で選ぶ
- `claude-code` では、AI のツールを全部オフにし、空のフォルダで動かし、API キーを渡さない
- テストでは偽物の実行役に差し替え、本物の AI を呼ばない
- AI の返事を待つ間の編集を消さないように、保存の直前に台帳を読み直す
