# 組み込み学習:F5 エラーの原因調査と、02「ボタンと割り込み」の準備

F5(デバッグ開始)で出たエラーを調べ、デバッガで止める意味と 01(Lチカ)の準備作業を説明しました。最後に、組み込み特有の部分を自分で書く形で `pico/02-button` を作りました。

## やったこと
- **F5 エラーの調査**:Debug Probe(PC と Pico をつなぐデバッグ用の機器)と Pico の接続や、各ツールの単体の動作に問題はありませんでした。
  - 最初に推測した「ELF ファイル(デバッグ用の情報が入ったビルド結果)の場所が渡っていない」は、エラーログから違うと分かりました。
  - 原因は、gdb(デバッガの本体)の起動が間に合わなかったことです。時間を測ると1回目は 7.4 秒、2・3回目は 0.08 秒でした。F5 で使う拡張 Cortex-Debug の待ち時間は 5 秒で固定され、設定では変えられません。
  - 1回目だけ遅い理由は、初回のファイル読み込みやウイルス対策ソフト(Defender)の検査と考えられますが、推測で未確認です。
- **gdb の空打ち(事前に一度起動しておくこと)を追加**:`tasks.json` に「Warm up GDB」を追加し、`launch.json` の2つの設定から F5 の直前に実行するようにしました。コミット `7d51354` を main に push しました。F5 での動作確認はしていません。
- **上の変更を取り消し**:依頼により revert(打ち消し)しました。コミット `e61de83` を main に push し、2つのファイルは変更前の状態に戻りました。
- **`pico/02-button` を作成**:ビルドと F5 の設定は 01 からコピーしました。表示、ループ、LED、方式の切り替え(`MODE`)は実装済みで、README には課題、調べる場所、確かめ方、折りたたんだヒントがあります。01 の README の「次は 02」のリンクも更新しました。コミット `b6f0e47` を main に push しました。
  - 課題の部分が空のままでも、両方の方式でビルドできます。ヒントの関数名とレジスタ名(チップの設定や状態を持つ場所の名前)は、SDK 2.3.1(Pico 用の開発部品集)にあることを確認しました。実機では未確認です。

## 説明したこと(学んだこと)

### F5 で同じエラーが出たとき
空打ち設定を取り消したので、初回の起動で「Failed to generate gdb commands」がまた出る可能性があります。もう一度 F5 を押せば通る見込みです。

### デバッガで止めると何が起きるか
- 動画の一時停止に近く、CPU が止まると LED の点滅もシリアル出力(Pico から PC に送る文字)も止まります。
- RP2040(Pico のチップ)のタイマーは、初期設定ではデバッガで止めている間カウントしません。そのため `sleep_ms` は、続行後に残りの時間を待ちます。`count` も飛びません。
- 確認するには、デバッガで `TIMER` → `TIMERAWL` の値が変わらないことを見るか、続行直後の LED が普段どおりの間隔で点滅することを見ます。
- PC 側の時間は進むので、USB のシリアルは切れます。このプロジェクトで Debug Probe の UART(別の通信線、U ポート)を使うのも同じ理由です。時間が関わる処理は、止めて調べるだけで動きが変わることがあります。

### Lチカで、ツール類を入れる以外にした作業
- 雛形を作り、`main.c` を「0.5 秒ごとの点滅と状態の表示」に書き換えました。
- `CMakeLists.txt`(ビルドの設計図)を Debug ビルドにしました。強い最適化がかかると、デバッガで変数が見えなくなるためです。「DO NOT EDIT」の部分は拡張が管理するので触っていません。
- `tasks.json` のビルドツールのパスが `ninja.exe.exe` になっていたのを直しました。
- ビルドが通ることを確認し、`README.md` と `SETUP.md` を書きました。
- インストール時に一部のツールが別の場所に入ったので、正しい場所へ移しました。

### 雛形の作り方
- Pico 拡張の「New Pico Project」の裏で動くスクリプト `scripts/pico_project.py` を、コマンドで1回実行しました。
- 実行したコマンドそのものは記録がなく、次の設定は生成されたファイルなどから逆算した推定です。プロジェクト名 `blink`、ボード `pico`、Debug Probe、シリアル出力は UART と USB の両方、VS Code 用の設定あり。
- `ninja.exe.exe` は、`.exe` 付きのパスを渡し、スクリプトがさらに `.exe` を足したためです。
- 自分で書くプログラムは `main.c` で、ほかは主にビルドや VS Code の設定です。出力先は `CMakeLists.txt` の `pico_enable_stdio_uart` などの 1 と 0 で切り替えられます。
